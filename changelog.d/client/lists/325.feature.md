- **Default filter inputs for date, time, duration, number, and multiple-choice filters (`fieldMappings`, `WidgetTagsInput`)**:
    - The filter menu offers `DateField`, `DateTimeField`, `TimeField`, `DurationField`, `FloatField`, `PositiveDecimalField`, `TypedChoiceField`, `MultipleChoiceField`, `ModelMultipleChoiceField`, and `DecimalInField` filters again, each with a default input. A filter of these types can be added, edited, cleared, and restored from its URL. `DurationSecondsField` leaves the filter value table, because no django-filter filter reports that type.
    - `AllValuesFilter` and `AllValuesMultipleFilter` filters report the `AllValuesChoiceField` and `AllValuesMultipleChoiceField` types, and their inputs are `WidgetModel` selects that fetch the values stored in the column.
    - The new `WidgetTagsInput` enters a list of values as tags, and `DecimalInField` filters use it with `numeric`, which accepts only entries written as decimal numbers. A refused entry stays in the input, marked invalid, and each entry is trimmed before the duplicate check. `TagsInput` forwards `convertValue`.
    - The list request repeats the query key once per value for `MultipleChoiceField`, `ModelMultipleChoiceField`, and `AllValuesMultipleChoiceField` filters, the form their `SelectMultiple` widget reads. The `in` filter types keep one comma-separated value. The new `repeatedKey` value-mapping key sets this for a custom type, and the list adaptors take the repeated keys as `repeatedParams`.
      _Remove any `mergeFilterFieldMapping` registrations added for these types when upgrading to 3.0.0-alpha.6, unless they customize the input on purpose. See [Filter Input Types](../../core-concepts/filtering-and-ordering-semantics.md#filter-input-types)._
