- **List views request the column totals they display (`useViewList`, `ViewList`, `storeModelInfo`, `storeModelConfig`)**:
    - Column totals are now opt-in on the server: a `list` request that names none gets an empty `columnTotals` back and costs no aggregation query. `useViewList` builds that request itself, sending the intersection of the totals the server advertises and the columns currently visible, under the totals query parameter (`ct` by default). Hiding the last totalled column stops asking for totals; showing it again restores both the request and the footer value. No app-specific configuration is needed for a declared total to keep rendering.
    - `storeModelInfo` requests and exposes the server's new `model_column_totals` section as `info.columnTotals` (`{ fields }`), and `storeModelConfig` derives `config.totalables` (the column names that can carry a total) from it. A server that advertises no section reads the same as a model with no totals: `totalables` is `[]`, and nothing is requested.
    - `COLUMN_TOTALS_PARAM` (`"ct"`) joins the query parameter constants in `@vueda/utils/constants`, alongside `PAGE_PARAM`, `SEARCH_PARAM`, and the rest. Which totals a model offers is discovered from model info; the parameter that asks for them is not.
      _A project that changes the server's `COLUMN_TOTALS_PARAM` setting must change this constant to match, the same as for every other wire parameter._
    - Totals arrive in the same response as the rows they describe, computed from the same queryset, and each response replaces `list.columnTotals` rather than merging into it. `useViewList` therefore sends every total it wants on every list request rather than topping up a previous one, so a footer value can never describe rows that have since changed.
    - Card layout asks for no totals at all. The footer is a table row and `ViewList` renders it only above the grid's table breakpoint, so a narrow viewport has nowhere to show a total and no longer pays the server an aggregation query per total to compute one. Crossing back above the breakpoint asks again. `useViewList` seeds this from the `tableBreakpoint` option rather than waiting for the grid to report its layout, so a phone-width load never sends the parameter in the first place instead of sending it and then refetching without it.
      _A custom `row-after-objects` slot that renders totals in card layout now receives an empty `columnTotals` below the breakpoint, and needs to request the totals itself. A shell calling `useViewList` directly should pass the same `tableBreakpoint` it gives `ObjectsGrid`; the default is `"lg"`, matching the component._
    - In "all pages" mode, `allPagePaginatedListCrudAdaptor` sends the totals parameter on the first page request only. The totals describe the whole filtered set rather than one page of it, so every page came back with the same numbers while running the aggregation again for each; only the first response's totals were ever read.
    - A model that advertises a total matching none of its configured display columns now logs a `console.error` naming it. Such a total is never requested and never rendered, and the server's own `vueda_info.E011` check cannot catch it, because total names are client column names and `displayFields` is configured per project and per view.
    - Totals now come back keyed by the column name the server declares them under rather than by the ORM field path it sums, so a total over a relation path (or over a renamed serializer field) lands in the footer cell for its column. `ViewList`'s footer row is unchanged: it still keys `list.columnTotals` by display column name, with a `field(<name>)totals` slot per cell and the `row-after-objects` slot for the row as a whole.
      _Requires a server with the column totals parameter and the `model_column_totals` metadata section. Against an older server no totals are requested and the footer row does not render. A server-side `column_totals` declared over an ORM path that is not also the display column's name now needs the mapping form (`{"price": "product_option__price"}`) for its total to render. See the server changelog._
