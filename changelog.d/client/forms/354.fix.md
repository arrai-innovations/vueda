- **The action form validation summary lists only the errors no field shows (`ActionForm`, `useForm`, `useField`, `FormField`, `useFieldSetInline`)**:
    - A failed action form repeated every field error in its validation summary, including the ones already rendered under their own field, and rendered that summary below the last field, where it read as that field's feedback and pushed the submit button down. The summary now lists only the field errors that no rendered field shows beside itself: an error on a field whose renderer failed, on a field rendered with `hidden`, on a field inside a collapsed inline field set, or on a key the form does not render at all. A form whose errors all render inline shows no summary, and expanding a collapsed inline field set moves its rows' errors out of the summary. A summary that does render sits above the first field, with the non-field error alert, so a reader meets it before the fields and the submit control. Form-scope non-field errors render there as before.
    - A bulk model action renders each selected record as a field that shows its own dry-run rejection beside the record, so such an action no longer shows a summary; the rejected records are found by their chips.
    - `useForm`'s context gains `registerShowsErrors(name, showsErrorsHook)`, which returns a registration id, `unregisterShowsErrors(id)`, and a `state.showsErrors` map keyed by field name. `useField` handles both calls and accepts a third `options` argument whose `showsErrors` function reports whether the calling component renders the field's error messages (default `true`); `FormField` reports `false` when `hidden`, and every field reports `false` while an enclosing `FieldSetStackedInline`, `FieldSetSingularStackedInline`, or `FieldSetTabularInline` is collapsed. A custom field component that renders no inline error messages should pass `{ showsErrors: () => false }` so its errors stay in the summary. A field still counts as showing its errors when its `field(fieldName)errors` / `field-errors` slot (or a field set's `field-set-level-chores` slot) is overridden, so an override that replaces those slots should render the errors it receives.
      _The `validation-summary` slot keeps its name and its `entries`, `count`, and `title` scope, but they now cover only the errors that survive this filter. An override that listed every field error will render fewer rows, and none when every error is shown inline._
