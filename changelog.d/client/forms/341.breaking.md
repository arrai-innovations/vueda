- **One `formProps` precedence in every form view (`ViewCreate`, `ViewUpdate`, `ViewRead`, `DetailView`)**:
    - Each view merges model config `formProps`, then its own `formProps` prop, then its own form props such as `fieldProps`, `widgetProps`, and `formModelVariant`. A form prop that the template does not pass leaves the configured value in place, and a passed value replaces the configured one whole. Each view ignores the `app`, `model`, and `view` keys in either `formProps` layer and logs a console warning.
      _On update, read, and detail views, check any key that model config `formProps` and the view's props both set: the view's prop now wins. Move a configured `app`, `model`, or `view` into the matching view layer of the model config._
