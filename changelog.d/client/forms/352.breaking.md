- **`submitFields` limits the request body, and `fetchFields` selects the save response (`useObjectForm`, `useViewCreate`, `useViewUpdate`, `ViewCreate`, `ViewUpdate`)**:
    - Create and update now send only the form values that `submitFields` names. A top-level name sends that field's whole value; a dotted path such as `address.city` sends only that nested value. Before this release, update sent every value the form held, including fetched fields with no input. A save could then write a stale value over another user's change.
    - The `f` parameter on a save request now comes from `fetchFields` instead of `submitFields`, so the save response carries the fields a retrieval would. `ViewCreate` gains a `fetchFields` prop.
    - `useObjectForm` accepts a `submitFields` prop. When it is omitted, the form sends every non-ignored value, as before.
    - An empty `submitFields` or `fetchFields` prop on a view now falls back to the model config, matching how an empty list in the config already falls back to the defaults.
      _Move any field that you added to `submitFields` only to read it from the save response into `fetchFields`. Check that `submitFields` names every value your forms must send, including fields that a custom layout or widget sets without a rendered input. See [Configure CRUDL Views](../../guides/configure-crud-views.md)._
