- **Rate-limited auth requests (`storeUser`, `RateLimitedError`)**:
    - `storeUser` actions reject a 429 response with `RateLimitedError`, a new error exported from `utils/errors.js`. Before, a 429 was an "Unexpected error occurred" error. The message says how long to wait when the server sends a `Retry-After` header. Without the header, it says to try again later. `retryAfterSeconds` holds the header's value, and it is `null` when the header is missing.
    - `forgotPassword` rejects a 429 with the same "Too many requests" message as the other actions. Its "Password reset requested too recently" message is gone, because the endpoint also answers 429 when one IP address sends too many reset requests.
    - `ActionForm` and `useActionForm` report a `RateLimitedError` only in the failure toast, with its message as the description. The form shows no error and stays usable, because the request fails only until the limit resets. Every auth view's form works this way. In `ViewTwoFactorAuth`, a refused code request does not start the resend countdown, so the user can pick another method right away.
