- **Removing a group's last permission keeps the group (`makegroupmigrations`, permissions overview)**:
    - The permissions overview recorded the removal of a group's last permission as a `deleted` change but kept the group, while the generated group migration deleted it, with its user memberships, in every other environment. Rolling back a migration that created a group also deleted it. The overview now records every permission removal as `unassociated`, and generated migrations never delete a group: a `deleted` change removes the permission and keeps the group, and rolling back an `added` change does the same.
      _Each group migration carries its own copy of the replay code, so migrations generated before this release still delete a group when they replay a `deleted` change or roll back an `added` one. Run `python manage.py updategroupmigrations` to rewrite existing group migrations with the current replay code; it keeps each migration's recorded changes. Otherwise, review group migrations that contain those changes before running them in another environment._
