- **Unsupported `PERMISSION_NAMES_MAPPING` values are a system check error (`vueda_core.E018`)**:
    - A mapping other than the default or the full mapping to Django's names created permission rows that `ObjectPermissions` never checked, so granting a renamed permission had no effect. A mapping to Django's names without `"list": "view"` checked a list against `view_` on the viewset and `list_` in row-level filtering. `manage.py check` now reports both as `vueda_core.E018`.
      _Django stops `migrate` and `runserver` on a system check error. Set the mapping to the default from `get_defaults`, or to `{"create": "add", "update": "change", "read": "view", "list": "view"}`. A changed mapping does not rename existing permission rows; move group assignments to the new codenames yourself._
