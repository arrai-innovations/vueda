- **Filter choices come only from rows the user may list**:
    - `model_info_filter_choices` built value-derived choices (`AllValuesFilter`, `AllValuesMultipleFilter`) from every row of the model, and related-model choices from every row of the filter's queryset, so a filter dropdown could show values from rows the user could not list. The endpoint now starts from the rows that the registered viewset's `get_queryset()` returns for a `list` request, then applies the same row-level and workflow state rules as the `list` view, for the `list` permission, to the model's rows and to the related model's rows. A related row the user may not list is not offered even when a visible row references it.
