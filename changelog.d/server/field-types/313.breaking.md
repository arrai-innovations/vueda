- **Durations render as JSON numbers**:
    - `get_defaults()` now sets `DEFAULT_RENDERER_CLASSES` to `vueda.core.renderers.VuedaJSONRenderer` instead of DRF's `JSONRenderer`. It is DRF's renderer with one change: `vueda.core.renderers.VuedaJSONEncoder` encodes a `timedelta` as a number of seconds rather than as the string DRF produces (`"3600.0"`). `VuedaJSONOpenAPIRenderer` does the same for DRF's own schema renderer. DRF reads the encoder off the renderer class rather than from a setting, which is why these are renderer subclasses rather than a settings entry.
    - This reaches any value that arrives as a `timedelta` without passing through a serializer field. The most visible case is a `Sum` over a `DurationField` declared in `column_totals`, which otherwise came back as a JSON string where the paginated response schema promises a number. A `DurationField` rendered through a serializer field is unaffected, because the field decides its own representation before the encoder sees it.
      _A project that sets `DEFAULT_RENDERER_CLASSES` itself, or names `rest_framework.renderers.JSONRenderer` on a viewset's `renderer_classes`, keeps DRF's string encoding; point those at the VUEDA renderers to pick this up. A client parsing the old string form of a duration needs updating either way._
