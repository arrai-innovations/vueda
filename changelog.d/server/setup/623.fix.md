- **Sentry reporting of server errors from DRF views**:
    - `debug_stack_exception_handler` now sends Sentry one event for each exception that it answers with a 500, such as a `RuntimeError` or an `ImproperlyConfigured`. Before, Sentry received no event for these errors, while a plain Django view's 500 produced one. Sentry marks the event as unhandled, as it marks a 500 from a plain Django view. Responses with a 4xx status, such as validation, permission, and confirmation errors, still send no event.
      _Expect new Sentry issues for API errors that went unreported before, and review alert rules that count unhandled errors._
