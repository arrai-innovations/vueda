- **`ExcludeFieldsSerializerMixin` without a view**:
    - A serializer registered with `register_serializer()` may now use `ExcludeFieldsSerializerMixin`. The `vueda_core.E009` system check is removed, so `manage.py check` no longer reports an error for that registration.
    - When the serializer's context has no view, or the view has no `action`, the mixin excludes no fields. Every field keeps its declared writability. Before this change, the mixin raised `KeyError: 'view'`. This happened in `/info/` for a `get_field_model_info` override that read `self.fields`, even when the serializer was registered with a viewset.
    - `vueda_core.E007` and `vueda_core.E008` still reject the mixin on a nested or expandable serializer. Their hints now explain that a nested copy would use the parent view's action, which is not supported.
