- **Viewsets with a custom `lookup_field`**:
    - Model info reports the `lookup_field` of a viewset that addresses objects by a field other than the primary key, and the detail routes, including `history-list`, `activate`, `deactivate`, and single-object delete, accept the viewset's own URL keyword. `VuedaFilterSet` and `VuedaCompositePrimaryKeyFilterSet` add a hidden `lookup` filter that matches the lookup values that a request repeats, as in `?lookup=A&lookup=B`. Bulk `pks` bodies, bulk errors and warnings, single-object `activate` and `deactivate` errors, and the workflow endpoints identify objects by primary key, and [Primary Key and Identifier Discipline](../../core-concepts/pk-and-identifier-discipline.md#lookup-field-and-lookup-value) describes the contract.
