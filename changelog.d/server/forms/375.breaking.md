- **List and detail requests report invalid `f` and `e` names as plain strings**:
    - An invalid `f` or `e` name used to return each error as an object, `{"name": [{"message": "...", "code": "invalid"}]}`. It now returns a list of strings, `{"name": ["..."]}`, the same shape as every other VUEDA validation error. These errors now carry `serverStack` and reach request logging and Sentry like other validation errors. One response now reports the invalid `f` and `e` names together, where an invalid `f` used to hide the `e` errors.
      _Read each error entry as a string, not through its `message` key._
