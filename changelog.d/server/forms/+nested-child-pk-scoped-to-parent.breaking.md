- **Nested writes match child pks only against the parent's own rows**:
    - A nested create or update matched each child row's pk against every row of the child model, then saved the match with its foreign key set to the parent in the request. A user allowed to update one parent could send the pk of another parent's child, and the write moved that row to their parent and changed it, with no check against the other parent. Reverse foreign key, reverse one-to-one, and generic relations now match pks only against rows that already belong to the parent. An entry whose pk matches none of those rows saves as a new row, as an entry with an unknown pk already did. Many-to-many relations still link existing rows by pk.
      _A client that moved child rows between parents by sending their pks under the new parent now creates new rows instead. Move a row by writing its foreign key on the child model itself._
