- **Queryset and manager orderings that the default ordering does not describe**:
    - The `vueda_info.E010` system check now reads what a viewset's `get_queryset()` returns, not only its `queryset` attribute, and compares nulls placement as well as fields and direction. A `get_queryset()` that needs the request is still checked through the `queryset` attribute.
    - The new `vueda_info.E015` check reports a registered model whose default manager orders its queryset by something `Meta.ordering` could declare, or by a name the query cannot resolve. A default manager may still order by an annotation it adds.
    - Both checks stop `runserver`, `migrate`, and the other management commands until the ordering is fixed.
      _Declare a viewset's default sort as its `ordering`, and a model-wide one as `Meta.ordering`, instead of calling `order_by()` in `get_queryset()` or in the default manager._
