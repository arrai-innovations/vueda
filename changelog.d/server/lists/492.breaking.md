- **Queryset and manager orderings that the default ordering does not describe**:
    - The `vueda_info.E010` system check now reads what a viewset's `get_queryset()` returns, not only its `queryset` attribute, including an ordering from the default manager and a `.reverse()`. It compares nulls placement as well as fields and direction, and a function such as `Lower("name")` counts as its own term. A `get_queryset()` that needs the request is still checked through the `queryset` attribute.
    - E010 reports an ordering by fields alone when the viewset declares no `ordering`, unless it matches `Meta.ordering` or comes from the default manager, which E015 checks. It reports an ordering that contradicts the model's `Meta.ordering` while the viewset declares none. When the viewset declares no `ordering`, it reports a grouped list queryset, such as one that annotates an aggregate. Django drops `Meta.ordering` from a grouped query. It reports an ordering that the viewset's `ordering` replaces, unless the ordering comes from the default manager. An ordering that names an annotation passes when no default ordering is declared. E010 also reports a `.reverse()` in the list queryset of a viewset that a client can sort, because Django keeps it through DRF's `order_by()` and every sort comes back in the opposite order. It reports a list queryset that Django rejects, from `get_queryset()` or the `queryset` attribute, with Django's own message. A viewset whose `filter_backends` leave out the ordering backend gets only that report, because nothing applies its `ordering`.
    - The new `vueda_info.E015` check reports a registered model whose default manager orders by fields alone, unless `Meta.ordering` declares the same order. A default manager may order by an annotation that it adds. E015 also reports a default manager whose query Django rejects, with Django's own message. That covers a query that fails when the manager builds it, and an ordered one that fails when E015 compiles it.
    - Both checks stop `runserver`, `migrate`, and the other management commands until the ordering is fixed.
      _Declare a viewset's default sort as its `ordering`, and a model-wide one as `Meta.ordering`, instead of calling `order_by()` with plain fields in `get_queryset()` or in the default manager._
