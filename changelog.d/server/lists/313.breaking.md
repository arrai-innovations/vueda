- **Column totals are opt-in and declared as a mapping**:
    - `ListRowLevelViewSetMixin.column_totals` is now a mapping of client-facing column name to the ORM field path aggregated for it (`{"product_price": "product_option__price"}`), replacing the list of field paths. The key is what a client requests and what comes back in the response's `columnTotals`; the value never leaves the server. Under the list form the ORM path doubled as the response key, so a total only reached a column when the two happened to be spelled the same, and a total declared over a relation path or over a renamed serializer field rendered nowhere with no error anywhere in the chain.
    - Totals are no longer computed on every `list` request. A request that names none returns `columnTotals: {}` and runs no aggregation query; one that names some aggregates exactly those, one `SUM` each. Previously every declared total cost a `SUM` on every `list` request whether or not the caller had a use for it, and a caller had no way to ask for a subset.
    - A declared path may only reach through relations that match at most one related row: a forward foreign key or a one-to-one, nullable or not. A reverse foreign key, a many-to-many, or a `GenericRelation` is rejected by `vueda_info.E011`, because the totals over real columns are computed in one `aggregate()` call and such a join adds a row per related object, inflating every one of them rather than only its own.
    - `ListRowLevelViewSetMixin.get_column_info` takes the requested total names as a second argument. `get_requested_column_totals` is the new hook that reads and validates them off the request.
      _Rewrite each `column_totals` list as a mapping, naming each total after the column that renders it. Run `manage.py check` to find declarations the mapping rules reject; `vueda_info.E011` names the viewset, the total, and the problem. Any caller that relied on totals arriving unasked must now send the totals parameter (`ct` by default) or a wildcard. Update any `get_column_info` override to the new signature._
