- **Ordering and ranking on a searched list that reaches through a multi-valued relation**:
    - An explicit `?o=` now sorts such a list the same way it sorts the list without a search, for every ordering the viewset offers, with the primary key breaking ties. An ordering that expands past a single column, such as `?o=customer` where `Customer` declares its own `Meta.ordering`, used to fall back to relevance order.
    - A ranked (`V:`) search returns each object once, ranked by its best matching row, and keeps an object when at least one of its matching rows reaches `search_threshold`. Result objects carry `combined_rank` only when the list is sorted by rank, and no longer carry the individual rank parts (`search_rank`, the trigram scores, `iregex_score`, `deterministic_score`).
    - `vueda.core.ordering.ordering_term_distinct_column` and `vueda.core.ordering.ordering_term_column_path` are removed. They paired ordering terms with `DISTINCT ON` columns for this search, which no longer uses `DISTINCT ON`.
      _Replace any code that reads the individual rank parts or `combined_rank` off an explicitly ordered searched list, and remove calls to the two removed helpers._
