- **Ordering, filter, and column total paths that end in a transform**:
    - A viewset's `ordering`, `ordering_fields`, and `nulls_ordering` may now name a path that ends in a transform, such as `created__year`, a key on a `JSONField`, or a transform that the project registers. The path may start from a model field, a queryset annotation, or `formatted_name`, including a related `formatted_name` reached through a lookup expression. `model_ordering` reports it under its dotted name, such as `created.year`, and types it from the transform's output, so a client can sort by it with `?o=created.year`.
    - A filter's `field_name` may apply a transform after `formatted_name`, such as `customer__formatted_name__lower`, and a `column_totals` path may end in a transform whose output can be summed, such as `hours__ceil` with `Ceil` registered on `DecimalField`. The system checks still report a misspelled or unregistered transform.
- **Default orderings that name an annotation (`model_ordering`)**:
    - A viewset `ordering` term that names an annotation from `get_queryset`, or a transform on one such as `-launched__year`, is now reported in `model_ordering.default` and `model_ordering.fields`. `default` used to come back empty for such an ordering, so the client's sort read-out showed no sort in effect.
