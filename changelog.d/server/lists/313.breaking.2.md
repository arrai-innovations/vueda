- **Column totals are aggregated only for a paginated response**:
    - `ListRowLevelViewSetMixin.list` now calls `get_column_info` after paginating, inside the branch that builds a paginated response, instead of before. A viewset with pagination disabled returns a bare array of rows with nowhere to carry `columnTotals`, so the previous ordering ran a `SUM` per requested total and discarded every result. Totals are still aggregated over the filtered queryset rather than the page, so a total covers the whole filtered set as before.
      _No change for a paginated viewset. A viewset with `pagination_class = None` never returned totals and now does not pay for them either; it should not declare `column_totals`._
