- **`updateworkflowmigrations` names the workflow behind a reused code**:
    - Migrations generated before this release refer to a workflow by its code alone, which cannot say which workflow a change meant once another model has taken that code over. The command now adds `historical_app_label` and `historical_model` alongside the code in every workflow reference in `changed_data`, working out what each code meant when each change was recorded from the workflow's own change. It adds to the change data and never removes from or alters it, leaves a workflow whose own change it cannot find as it is, and makes no further difference when run again. `changed_data` is now rewritten in the form `makeworkflowmigrations` writes it, so a comment written inside that list is not kept; hand-added imports and functions elsewhere in the file still are. A migration whose `changed_data` cannot be read, because the file has a syntax error or has been altered so that it no longer runs on its own, is skipped in full and reported, and the command finishes with a failure rather than rewriting a file it cannot read. A `history_date` recorded without a time zone, which only a hand edit produces, is reported and read as UTC so that it still orders against the dates other migrations recorded, and is left in the file as it was written.
      _Run `python manage.py updateworkflowmigrations` once in your project and commit the rewritten migrations. The app label and model name live in the migration files, so this fix reaches a project only when those files are updated and committed; running the command during a deploy does not carry the fix forward, because the files it rewrites are not the ones the next deploy starts from. Migrations generated before this release keep working until a workflow code is taken over by a different model, at which point a change naming a workflow by code alone can no longer say which workflow it meant. It is safe for migrations already applied elsewhere, because the change data describes the same workflow records either way._
