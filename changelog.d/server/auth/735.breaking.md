- **Reauthentication for `recent_auth_required`**:
    - A sign-in no longer counts as a recent reauthentication, so a user who has just signed in confirms their password or second factor once before a guarded request, and `auth_pending_flow` names that flow. A user with a two-factor device can reauthenticate only with a code, so the `reauthenticate` endpoint answers `403` for that user, and a user with neither a usable password nor a device is refused on every guarded request. `ACCOUNT_REAUTHENTICATION_METHODS` now defaults to `password` and `mfa`, and `vueda.core.reauthentication.RECORD_METHOD_BY_FLOW` is removed.
      _If you built your own reauthentication view, send a user with a two-factor device to the code form, as [Build a Re-Authentication View](../../guides/build-auth-views.md#build-a-re-authentication-view) describes._
