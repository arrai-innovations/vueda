- **allauth headless routes under `vueda.user/_allauth/`**:
    - `vueda.user.urls` now mounts only `_allauth/browser/v1/account/authenticators/recovery-codes`, which the recovery-codes view calls. The other allauth headless routes return 404: `config`, `auth/session`, `auth/login`, `auth/signup`, `auth/reauthenticate`, `auth/code/confirm`, `auth/password/request`, `auth/password/reset`, `auth/email/verify` and `auth/email/verify/resend`, `auth/phone/verify` and `auth/phone/verify/resend`, `auth/2fa/authenticate`, `auth/2fa/reauthenticate`, `account/password/change`, `account/email`, `account/phone`, `account/authenticators`, and `account/authenticators/totp`. They let a caller create accounts, add email addresses, reset or change passwords, and add or remove a TOTP authenticator outside VUEDA's own views.
      _If your project calls one of these routes, use the matching VUEDA endpoint, or mount the allauth view in your own URLconf._
