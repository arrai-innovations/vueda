- **Status updates reach a queue item that stores no provider ID (`send_sms`, `send_email`, `VDQ_EMAIL_TRACKING_STRATEGY`)**:
    - `send_sms` adds the queue item's key to the Twilio `status_callback` URL, and `send_email` adds it to the email's Anymail `metadata` under `vdq_queue_item`. A Twilio status callback or Anymail tracking event that names no stored `MessageSid` or `message_id` finds the item by that key, stores the ID, and applies the status. An item that stores a different ID is left unchanged and the update is logged.
    - `VDQ_EMAIL_TRACKING_STRATEGY` selects the class that attaches the key to an email and reads it back from a tracking event, as a class or dotted path. `vueda.vdq.tracking.EmailTrackingStrategy` attaches nothing; subclass it to carry the key another way, such as in a tag. See [Matching a status update to its queue item](/core-concepts/vdq-and-background-work#matching-a-status-update-to-its-queue-item).
      _On an ESP that accepts no metadata, Anymail refuses the first send and VDQ sends each email again without the key, with an info log. Set `VDQ_EMAIL_TRACKING_STRATEGY` to the no-op strategy or a custom one to send on the first attempt._
